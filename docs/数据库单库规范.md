# 数据库单库规范

## 目标

本项目只允许存在一个“权威数据库”：

`%APPDATA%\local.novel.cockpit\novel.db`

所有运行形态都必须读写这一份库：

- 浏览器前端
- FastAPI 后端
- MCP 服务器
- Cherry Studio 中转调用

如果再次出现多个 `novel.db`，以这个 AppData 路径为准，其余都视为缓存、旧构建产物或误启动生成的副本。

## 读取优先级

1. 显式环境变量 `NOVEL_COCKPIT_DB`
2. Windows 用户目录下的 `%APPDATA%\local.novel.cockpit\novel.db`
3. 仅在极端兜底情况下，才考虑其他路径

当前代码已经按这个顺序工作。`NOVEL_COCKPIT_DB` 适合测试、临时迁移和特殊调试；日常使用时建议不手动改它。

## 启动约定

- 前端开发入口和启动脚本都会把 `NOVEL_COCKPIT_DB` 指向 AppData 库。
- `scripts/start-mcp.ps1` 也会设置同样的数据库路径。
- `scripts/start-backend.ps1` 已补齐同样的环境变量，避免 Python 直启时落到仓库里的旧库。
- `backend/app/db.py` 的默认路径也已经切换到 AppData，确保即使手动执行 `python -m app.main`，依然写同一份库。

## 不再使用的库

下面这些库如果还存在，只能算历史遗留或构建副本，不应再作为正式数据源：

- `backend/data/novel.db`
- `frontend/src-tauri/target/...` 下的旧桌面壳构建数据

如果你已经确认 AppData 库里的数据是最新的，就可以删除这些副本，避免后续再次连错库。

## 排查方法

当前端看起来“什么都没有”时，先检查这三项：

1. `GET /api/dashboard` 返回的 `project.id` 和 `project.title`
2. 当前项目是否被切到了别的书
3. `pending_changes` 是否只是还没批准，所以正式表里没有数据

如果 `GET /api/dashboard` 里显示的是空项目，但 AppData 库里有内容，通常就是后端进程没有使用同一份 `NOVEL_COCKPIT_DB`。

## 迁移建议

如果以前已经写过内容到别的数据库：

1. 先把旧库里的数据导出成项目 JSON。
2. 再导入到 AppData 这份权威库里。
3. 确认前端显示正常后，再删除旧库。

这样可以保住历史数据，也能把后续写入路径收束到单库。
